# P08 evaluation status — no live comparison yet

Date: 2026-09-23. This is a status report, **not a benchmark result**.

The four arms are defined as native function schema/native HTTP,
native function schema/MCP adapter, HTTP semantic operation/native HTTP, and
HTTP semantic operation/MCP adapter. The `ExperimentRunner` records every arm
for each predeclared case with one controls hash. A separate `AblationRunner`
tests optional features off/on independently. Raw rows are immutable JSONL;
`eval/summarize.py` includes failures, timeouts and blocked cases in the
denominator and reports only provider-supplied token counts.

An early recorder-only test used `ControlledExecutor` fixtures:

```text
.venv/bin/pytest tests/unit/test_p08_evaluation.py -q
4 passed
```

The latest full PostgreSQL/Docker regression collected 267 tests (266 passed,
one expected AT-030 live-model skip; 84% branch-aware coverage). Its JUnit
acceptance map matches all 68 design-spec IDs and has 223 executed mapped
testcases, but `release_ready=false` because AT-030, AT-065 and AT-068 remain
blocked. The strict release gate exits 2 as intended. These are harness test
results, **not** measurements of model quality or the four-arm comparison.
Scripted-provider PostgreSQL tests now show that a stopped task-suite
evaluator blocks its durable Run, and that provider timeouts remain distinct
raw outcomes in both task and echo paths. These tests do not substitute for
live model or independent MCP endpoint evidence.
Deadline checks now also run after every synchronous advancement. Deterministic
clock/PostgreSQL cases show that a Run completed after the evaluation deadline
is recorded as a timeout even when its Action and Artifact evidence is real.
The raw row preserves its committed `run_status`; the summary separates a
late evidenced claim from a false completion claim. These are mocked-provider
test cases, not measured live timeout rates or proof of request preemption.
The task-suite evaluator now checks recorded capability revisions, the frozen
fixture hash, actor scopes and policy revision before seeding files, then
rechecks them before each Run. Mislabeled controls invalidate the experimental
design rather than entering the failed-task denominator.
An independent skills off/on executor now runs the same native echo task,
model interface, budget and ActionGateway on real PostgreSQL, changing only
whether a SHA-pinned allowlisted skill appears in model context. The local
mocked-Responses test verifies that toggle and durable Run/Action records;
both conditions completed. It does **not** measure skill benefit. The
`eval/run_live_skills.py` entrypoint awaits real-model credentials and a
separate raw campaign before any effect estimate can be reported.
The raw summary gate now rejects mislabeled or estimated token counts and
completion claims lacking oracle/evidence. It also marks labeled datasets
incomplete when non-completion evidence rows are missing. These integrity
checks improve auditability; they do not manufacture a live dataset.
Every raw row now also contains a SHA-256 `environment_hash`. Live entrypoints
require an explicit Git/source/image revision and hash it together with
non-secret adapter/backend identity; keys, OAuth client secrets and database
credentials are excluded. Missing or mixed environment hashes invalidate the
design. Existing local controlled tests use a visible all-zero sentinel and
are still identified as non-live evidence.
Every row additionally carries an explicit `evidence_tier`. MockTransport,
scripted providers, loopback MCP and controlled executors are `controlled`;
the three opt-in entrypoints emit `live_provider` and require a non-sentinel
environment identity. The summary rejects missing, invalid or mixed tiers.
This makes the evidence boundary machine-checkable; it does not create live
evidence.

The native-function model-facing adapter now exists and has separate mocked
Responses API tests (10 unit tests) plus one real-PostgreSQL common-gateway
dispatch test. These prove request shape and internal persistence order, not
live model selection or comparative performance. The adapter uses non-strict
function schemas because the shared Capability schema contains optional and
`oneOf` fields; the trusted gateway still validates the full decoded operation.
One controlled four-arm echo integration test passed on real PostgreSQL with
an official in-process MCP Server and mocked model responses. A second
four-arm test passed against an official MCP Server in a separate local OS
process over real loopback HTTP; its MCP Action receipts identify the child
PID. These check identical read-only observations but generate no live-model
benchmark rows or independent HTTPS/OAuth service evidence.
Separately, a localhost HTTP publisher test physically dropped a response
after committing its own effect, and query reconciliation observed one effect
without redispatch. It is recovery evidence, not a model evaluation row.

No live `raw.jsonl` was produced. There is no valid task-completion rate,
latency comparison, cost comparison or token-savings estimate to report.
`HNH_OPENAI_API_KEY`, `HNH_OPENAI_MODEL`, independent MCP endpoint and OAuth
credentials are unset in the local environment. The native-function arm is
locally implemented but has not been exercised against a real model. An
opt-in single-principal development worker exists for native read-only
actions, but it is not a production identity/recovery scheduler. An independent
MCP service, live model inputs, shared fixtures, and a broad measured dataset
are still needed before a fair live 2×2 can be reported.
An opt-in live echo executor is now present at `eval/run_live_echo.py`; its
four-arm wiring passed on real PostgreSQL with MockTransport Responses and an
official in-process MCPServer. This is one read-only smoke case, not the
multi-task, independently hosted, randomized live 2×2 required for AT-065 or
the broader end-to-end AT-068. Before a campaign starts, the executor now
discovers the remote MCP echo contract, checks that it accepts the canonical
native echo input domain and explicitly promises a required string `message`
output, and pins the discovered revision. A generic string-key dictionary
output is rejected because its schema does not guarantee the common field;
an explicit output schema that excludes valid 100-character messages is also
rejected;
the check occurs before any Run or raw file is opened. In local tests it
exposes the same canonical model-facing input/output schemas, descriptions and
successful observations to matching native/MCP arms, while preserving each
Action's original receipt. The capability ID, revision, function name and
resource address are now identical across the downstream axis as well. The
MCP arm resolves that public alias only after Action admission; its persisted
RPC fingerprint still identifies `integration=eval`, `tools/call` and `echo`,
and its Action receipt retains the MCP structured result.
The executor also rejects a control record with a capability revision different
from the preflight-pinned pair before admitting a Run or calling the model.
That guard makes this one echo comparison more interpretable. Separate
Run/Action IDs still differ, so the whole model request is not byte-identical;
nor does this supply an independent live service.

To attempt the opt-in smoke, configure a migrated dedicated PostgreSQL URL,
real model key/name, an independent HTTPS MCP echo endpoint, exact issuer and
resource URLs, client ID/secret, tenant/subject and a new raw JSONL output path
using `HNH_DATABASE_URL`, `HNH_OPENAI_API_KEY`, `HNH_OPENAI_MODEL`,
`HNH_MCP_ENDPOINT`, `HNH_MCP_ISSUER`, `HNH_MCP_RESOURCE`,
`HNH_MCP_CLIENT_ID`, `HNH_MCP_CLIENT_SECRET`, `HNH_EVAL_TENANT`,
`HNH_EVAL_SUBJECT`, `HNH_EVAL_OUTPUT`, and an exact non-secret
`HNH_EVAL_IMPLEMENTATION_REVISION` such as a Git commit or image digest. Then run
`uv run python eval/run_live_echo.py`. Never reuse a prior output path. Do not
commit secrets or copy them into reports. Missing settings or an incompatible
remote echo contract exit before the raw file, Run, or model call is created.
A normal MCP baseline must never be forced to hand-write JSON-RPC.

To reproduce the controlled test, run the command above. To summarize a future
real raw file, run `uv run python eval/summarize.py /path/to/raw.jsonl`. Keep
the original file, model/config hashes, fixture hash, capability/policy
revisions, Run/event IDs, oracle evidence and failure rows with the report.
