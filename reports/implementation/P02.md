# P02 implementation report

Date: 2026-09-22 (Australia/Sydney)

Status: **complete** for the P02 exit gate. The runtime now has one authorized
HTTP operation path for native effects, transactional managed files, immutable
artifacts, and a versioned discovery surface. It does not yet contain the P03
model loop, CompletionGate, persisted event streaming, or production adapters.

## Delivered behavior

- A trusted, revisioned `CapabilityRegistry` with stable ID ordering, opaque
  revision-bound cursors, per-tenant/subject/scope cache keys, and dispatch-time
  authorization independent of discovery cache hits.
- Capability detail and subject-filtered OpenAPI export. The runtime advertises 13
  implemented target operations; 10 future operations remain absent.
- Strict untrusted `HttpOperation` parsing: relative `/v1/` targets only, four
  model-controlled headers only, no caller identity/credentials, deterministic
  fingerprints, and a maximum JSON depth of 32.
- A second validation layer using each resolved Capability's JSON Schema before
  Action admission or adapter dispatch.
- `ResourceDispatcher` as the HTTP-native resource entry point and `ActionGateway`
  as the common HTTP/in-process binding, policy, admission, and execution path.
  `execute_bound()` accepts only an already-admitted Action and never recursively
  calls a public local endpoint.
- Action slots are unique by `(run_id, turn_id, call_index)`. Replay verifies the
  request hash and capability revision, then returns committed evidence rather than
  creating another Action.
- Direct HTTP effects receive an implicit durable Run. The kernel advances that Run
  through `running` to `succeeded`/`failed`, commits events, and retires its initial
  wakeup job. Only `RunController` changes Run/Action state.
- Managed logical workspace files backed by immutable Artifact bytes and a
  transactional PostgreSQL version pointer. New files require `If-None-Match: *`;
  overwrite requires the current strong `If-Match` ETag.
- Deterministic PostgreSQL advisory locks plus row locks serialize a logical path,
  including the absent-row create case. Request idempotency is also serialized and
  stored transactionally with the resource result.
- Artifact create/metadata/content routes with SHA-256, strong ETag, subject/tenant
  authorization, and immutable content. This P02 slice stores at most 1 MiB per
  artifact in PostgreSQL.
- Canonical logical path validation rejects traversal, residual percent encoding,
  absolute paths, backslashes, NUL, dot/empty segments, and never dereferences host
  filesystem symlinks.
- GET resource routes authorize and bind the capability but do not create Actions,
  invoke an adapter/model, or mutate business resources.

## Decisions, limits, and next safe action

- Catalog definitions and trusted bindings are immutable in-process configuration
  in P02; there is deliberately no model-accessible registration/admin endpoint.
- Artifact bytes are stored in PostgreSQL for this bounded slice. A production blob
  adapter and orphan GC are later storage work; no filesystem fallback exists.
- `native.echo` is a real deterministic local adapter used to compare ingress paths.
  It is not evidence of external HTTP, MCP, model, or sandbox interoperability.
- There is no outbound HTTP adapter in P02, so AT-014 proves rejection before any
  dispatch surface exists; it does not claim full SSRF defenses for a future client.
- Local Action admission/execution is deduplicated. No general exactly-once claim is
  made for future remote effects.
- Docker remains unavailable, which does not block P02 but will matter for P04.

Next: P03 should persist complete ModelCalls before action dispatch, implement the
small Runner loop and ContextBuilder, expose committed event history/SSE, and gate
Run success on committed evidence through CompletionGate.
