# P03 implementation report

Date: 2026-09-22 (Australia/Sydney)

Status: **blocked_environment at the P03 exit gate**. AT-022–AT-029 pass on
real PostgreSQL. AT-030 has an implemented live-provider test, but the explicit
live-test flag, API key, and model were absent, so no external model request was
attempted and no live success is claimed.

## Delivered behavior

- A narrow `ModelProvider` protocol, deterministic `ScriptedProvider`, and an
  OpenAI Responses API adapter using non-streaming strict structured output. The
  adapter sends no hosted tools, sets `store: false`, records returned usage, and
  persists only visible message output rather than hidden reasoning items.
- A persisted serial `Runner` loop. It freezes a versioned Context snapshot,
  writes ModelCall intent and attempts, stores the complete visible response and
  parsed output, and only then binds/admitted Actions into stable
  `(run_id, turn_id, call_index)` slots.
- Explicit fault hooks on both sides of the response commit. Recovery before the
  commit repeats the provider call but cannot execute an uncommitted fragment;
  recovery after the commit reuses the durable output and does not call the model
  or create the same Action twice.
- Bounded invalid-output repair and repeated-response no-progress termination.
  Invalid feedback is retained in committed events and included in later context.
- Persistent budget reservations serialized by the Run budget row. Model turns,
  output-token upper bounds, and tool calls reserve before work and settle actual
  usage separately; release restores capacity.
- `ContextBuilder` snapshots include goal, Run status, remaining budget,
  scope-filtered capability summaries, recent committed events, and Action
  observations. Oversized observations keep an authorized source URL, version,
  and request hash. Recognized secret fields are redacted from model context.
- `CompletionGate` treats model completion as a candidate. It verifies Artifact
  visibility/run provenance, succeeded Action or committed Event evidence, and
  absence of unresolved Action states before the kernel can commit `succeeded`.
  Acceptance and regression results are stored separately.
- JSON event history and SSE replay over the same committed Event rows. Resume is
  strictly after `Last-Event-ID`; disconnect does not cancel a Run. Expired and
  future cursors fail before streaming with 410/409 problem bodies and Link/header
  recovery locations.
- The P03 migration adds complete ModelCall payloads/attempts, Context snapshots,
  budget reservations, Completion records, Action-linked events, and final
  Run result/failure fields.

## Limits and next safe action

- The SSE endpoint streams the current retained committed page and closes; clients
  reconnect with the last sequence. A long-held push tail/heartbeat optimization is
  not claimed.
- The callable Runner is implemented and exercised directly; a continuously
  supervised worker process and lease-expiry recovery loop remain later runtime
  work.
- Model turns, tool calls, and output tokens are enforced. Provider-price-derived
  cost and wall-clock deadline enforcement are not claimed in this slice.
- Durable user input/approval requests remain P05 work; a model request for input
  is rejected with bounded invalid-output handling rather than held in memory.
- No sandbox, Python execution, remote-effect reconciliation, or MCP behavior is
  claimed by these results.

To close P03, explicitly configure `HNH_RUN_LIVE_TESTS=1`,
`HNH_OPENAI_API_KEY`, and `HNH_OPENAI_MODEL`, then run the recorded AT-030 command.
The test must complete the read → uppercase transform → immutable Artifact chain,
verify the bytes, reach evidence-gated success, and record nonzero real usage.
