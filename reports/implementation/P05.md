# P05 implementation report

Date: 2026-09-22 (Australia/Sydney)

Status: **complete**. AT-039–AT-052 pass against real PostgreSQL. P03's
independent live-provider AT-030 remains `blocked_environment`; no scripted model,
fault driver, or deterministic resolver result is counted as live-provider evidence.
Consequently P05 is complete, while the repository-wide v0.1 exit is not yet fully
closed.

## Delivered behavior

- Durable `InputRequest`/`InputResponse` records for exact-bound approvals and model
  clarifications. Approval binds tenant, subject, action request hash, capability and
  policy revisions, scope fingerprint, resource versions, expiry, and request version.
- One-response compare-and-swap with idempotent replay, expiry handling, restart-safe
  `waiting_input`, a durable wakeup after an answer, and dispatch-time reauthorization.
  The Runner now persists `request_input`, waits, and resumes with the submitted values
  in committed event context.
- A recovery coordinator and effect-driver port that distinguish `read_only`,
  `local_transactional`, `remote_idempotent`, and `unsafe` behavior. Ambiguous unsafe
  writes become `outcome_unknown`; they are queried or explicitly reconciled rather
  than resent. Remote-idempotent retries reuse one downstream business key.
- Persistent Action attempt receipts, upstream handles, downstream idempotency keys,
  cancellation receipts, reconciliation records, and checkpoints. A restricted HTTP
  reconciliation route records operator evidence without asking the model to guess.
- Database-time job leases with monotonic lease epochs. A stale worker cannot start a
  dispatch or commit a result after another worker takes ownership.
- Cancellation as intent: pre-dispatch Actions are stopped, new dispatch is refused,
  and a remote cancellation ACK without confirmed stop remains `waiting_external`.
  Budget termination blocks instead of claiming clean failure while effects remain
  unresolved.
- Later P08 hardening found and fixed a multi-Action cancellation edge: manual
  reconciliation no longer terminalizes a Run while another Action remains
  unresolved; `confirmed_not_applied` under cancellation becomes `cancelled`,
  not dispatchable `ready`. The same all-Actions check guards MCP Task cancel
  finalization. Two real-PostgreSQL cases cover second-Action applied and
  not-applied outcomes, each with one committed `run.cancelled` event.
- Recovery compatibility checks that block with `migration_required` when a checkpoint
  references a removed capability revision or incompatible policy/schema version.
- Central recursive redaction for committed events and model context, including
  secret-key names, bearer tokens, and common `sk-` canaries.
- An outbound policy that accepts only registered HTTPS destinations/ports, rejects
  credentials and non-global resolved addresses, re-resolves each redirect hop,
  returns validated addresses for connection pinning, limits redirects, and strips
  credentials on cross-origin redirects.
- Three trusted HTTP operations: read/respond to input requests and submit Action
  reconciliation. Runtime OpenAPI now exposes 21 of the 23 target operations.

## Limits and next safe action

- `FaultEffectServer` is a deterministic in-process adapter, not a remote network
  service. It verifies recovery decisions and durable ledgers, but not real proxy,
  TLS, socket-reset, or downstream deployment behavior.
  A later P08 localhost HTTP test covers one real TCP response-loss window after
  an independently counted effect; it still does not establish production
  egress, TLS, or full model-to-publisher behavior.
- The egress policy was tested with a controlled resolver and redirect inputs. A
  production HTTP adapter must actually connect to the returned validated address,
  preserve TLS hostname verification, and supply packet-capture evidence; this stage
  does not claim a production egress broker exists.
- The current redactor covers structured secret keys and recognizable token values;
  arbitrary secrets embedded in unlabelled natural language require broader DLP and
  access-controlled raw evidence handling.
- Reconciliation is a trusted manual/API decision with evidence IDs; no operator UI,
  external ticket verification, or dual-control workflow is implemented.
- Fencing strictly protects local state. It cannot make an external API honor lease
  epochs, so external exactly-once is not claimed.
- Ordinary Docker isolation remains the P04 boundary and is not proof for hostile
  multi-tenant production execution.
- The only skipped acceptance case is P03 AT-030, which still requires explicit live
  OpenAI configuration.

The next stage is P06: implement and test truthful modern and legacy MCP profiles,
MRTR/task continuation, result classification, and issuer-bound credentials against
actual SDK/server behavior while routing every effect through the existing kernel.
