# P06 implementation report

Date: 2026-09-22–23 (Australia/Sydney)

Status: **local P06 acceptance complete; independent remote/production OAuth not claimed**.
AT-053–AT-059 have passing local interoperability/security evidence, scoped below.
P03's unrelated live-model AT-030 remains `blocked_environment`. Neither the
official local MCPServer fixture nor the in-memory credential vault is presented
as an independent remote deployment or production OAuth integration.

## Delivered behavior

- An optional MCP adapter around the installed official `mcp==2.2.0` and
  `mcp-types==2.2.0` packages, with explicit `modern2026-07-28` and
  `legacy2025-11-25` profiles. The core still runs without MCP.
- Scope/subject/tenant/profile/policy-partitioned capability import. Remote tool
  annotations do not assign local effect semantics; trusted bindings do.
- Separate durable paths for JSON-RPC protocol errors, tool-level `isError`,
  `input_required`, and Tasks handles. Arbitrary JSON `structuredContent`, including
  an array, is preserved.
- PostgreSQL MCP RPC, continuation, and task ledgers. MRTR resumes the same admitted
  Action after a persisted InputRequest, preserving opaque requestState outside model
  context. A response-loss case becomes `outcome_unknown` and does not resend the
  original tool invocation.
- Tasks get/update/cancel are distinct methods. A task handle survives restart;
  polling does not recreate the task; cancel acknowledgement is not treated as
  confirmed stop. Lease checks fence stale poll workers before remote polling and
  before committing observations/results. An initially terminal task completes its
  Action exactly once.
- Exact local credential reference binding by integration, tenant, issuer, resource,
  and subject, with HTTPS endpoint/audience matching, timezone-aware expiry and local
  revocation checks. The MCP HTTP client disables redirects and environment proxy
  inheritance; an injectable transport supports controlled integration testing.
- A separate optional official `ClientCredentialsOAuthProvider` transport now performs
  actual OAuth metadata discovery/token exchange with a pinned HTTPS issuer and
  trusted client-credential vault/storage ports. The same transport discovered an
  official MCPServer behind a local OAuth challenge. Mock transport tests proved
  a malicious advertised issuer or mismatched metadata issuer never received a
  client-secret token request. OAuth bearer stayed at the MCP resource and client
  Basic authorization stayed at the pinned issuer token endpoint. Local token
  storage/vault are deliberately in-memory; managed secrets and independent
  remote deployment remain untested. Further mock-transport tests prove that
  revocation after token issuance blocks the next request before HTTP dispatch,
  and that a resource 401 causes a second client-credentials exchange at the
  same pinned issuer before the new bearer reaches the resource.
- The official SDK used here does not bundle a Tasks client. The project implements
  the draft extension through the SDK's formal extension API and advertises Tasks
  only when explicitly enabled and server-advertised. No upstream SDK feature claim
  is inferred from the protocol version.
- A trusted `MCPIntegrationManager` now composes approved bindings into a
  request-scoped capability catalog and ActionGateway. The ASGI catalog and
  invocation path use the same scope-filtered binding; model requests cannot
  register arbitrary integrations. A PostgreSQL-backed HTTP test verified one
  admitted call/replay and denied discovery/invocation for an unauthorized subject.
- A separate-process loopback interoperability test now launches the official
  MCPServer under Uvicorn, discovers its tool through the project's SDK adapter
  over a real TCP/HTTP connection, and confirms the echo result comes from the
  child OS process. This test-only transport is unauthenticated HTTP on
  loopback; it does not replace independent remote HTTPS/OAuth evidence.

## Limits and safe continuation

- The ASGI factory accepts a trusted integration manager and does scoped
  discovery/invocation. It is not yet wired to a production configuration or
  managed credential backend; default operation remains native-only.
- Credential binding and SDK client-credentials flow use an in-memory vault and
  token store with local revocation and mock issuer metadata, not a managed issuer,
  live token-refresh drill, or secret-at-rest backend. The local 401 drill only
  reacquired a token from a pinned mock issuer. Endpoint matching and
  `follow_redirects=False` do not replace a
  connection-pinned egress broker or independent network attack tests.
- The local official-server fixture validates the SDK protocol path but is not
  evidence of third-party modern/legacy/Tasks interoperability. The Tasks extension
  is draft-profile-specific; only tested fields/methods are advertised.
- The MRTR continuation's opaque requestState is excluded from model-facing event
  data, but is stored in PostgreSQL without encryption-at-rest in this stage.
- Only form elicitation is supported. Unsupported MCP input modes and arbitrary
  server extension combinations are not claimed.
- The two conversation API operations remain unimplemented and are not advertised.

Next, connect the trusted OAuth client credential/storage ports to a managed
secret backend and independent issuer/server, exercise refresh and remote
interoperability, then upgrade the compatibility claim. This local P06 exit
does not establish production readiness. The independent live-model AT-030
requires its own configuration.
