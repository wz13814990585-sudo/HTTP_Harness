# P04 implementation report

Date: 2026-09-22 (Australia/Sydney)

Status: **complete**. AT-031–AT-038 pass on real PostgreSQL; AT-032–AT-036
also pass against a real Docker Engine using a locally cached Python image pinned
by sha256 digest. P03's independent live-provider AT-030 remains
`blocked_environment`; no P04 result is counted as model-provider evidence.

## Delivered behavior

- Narrow `ExecutionBroker` and `BlobStore` ports plus trusted, immutable sandbox
  profiles. Callers select a registered profile ID; they cannot provide an image,
  mount, Docker socket, network mode, entrypoint, or arbitrary runtime flag.
- A fail-closed unavailable broker. When no digest-pinned sandbox image is
  configured, execution session creation returns `execution_unavailable` and does
  not start a host process.
- A Docker broker whose fixed command applies `--network=none`, non-root
  uid/gid 65534, read-only root, all capabilities dropped, no-new-privileges,
  bounded CPU/memory/PIDs/file descriptors/tmpfs, no host bind mounts, no Docker
  logs, and a per-cell deadline. The image must include `@sha256:` and is never
  pulled implicitly.
- A fixed JSON-lines Python daemon inside the container. Cells share one namespace
  within a generation, execute under a session lock, and preserve stdout, stderr,
  typed Python exceptions, duration, transport status, and bounded exported files.
  Timeout or protocol/process loss destroys the sandbox and commits explicit loss.
- Durable PostgreSQL `ExecutionSession` and `Execution` records. The kernel owns
  admission, cell indices, ready/busy/lost transitions, generation replacement,
  receipts, and committed execution events; the broker cannot directly mutate
  durable state.
- `execution.session.create`, `execution.session.read`, and `execution.python`
  capabilities routed through the same `ActionGateway`. An application-level
  Python failure commits the Action as failed even when broker transport succeeds.
- Content-addressed filesystem blobs published through write/fsync/atomic rename,
  with Artifact metadata committed afterward. Reads verify bytes against metadata;
  orphan keys can be collected without exposing a dangling Artifact reference.
- Automatic import of regular, non-symlink files below `/workspace/outputs` into
  immutable Artifacts. Total exported bytes and broker response bytes are bounded.
- The public code endpoint accepts `text/plain`; pickle media types are rejected
  with 415 before Action admission or any deserialization.

## Limits and next safe action

- This is a constrained Docker execution boundary validated on the local Docker
  Desktop engine. It is not a claim that ordinary containers alone are sufficient
  for hostile multi-tenant production workloads; stronger isolation/runtime policy
  and deployment hardening remain necessary.
- Live sandbox handles are process-local. Durable generation and loss facts survive,
  but after Harness restart the current implementation reconciles an absent handle
  as lost; it does not reattach to an already-running container.
- Timeout terminates the whole generation, not just one Python cell. This is
  conservative and prevents an interrupted cell from leaving unknown in-memory
  state, at the cost of requiring explicit generation replacement.
- Artifact import is one file at a time. Content publication is atomic and orphan
  safe, but a multi-file result is not exposed as one all-or-nothing manifest.
- Filesystem blobs are suitable for this modular-monolith slice. Shared production
  workers require a common durable blob backend and retention/GC scheduling.
- Shell execution, user-supplied packages, host mounts, and sandbox network access
  are intentionally unsupported. There is no fallback to host `exec()`.
- P03 AT-030 still requires explicit live OpenAI configuration and remains blocked.

The next implementation stage is P05: bind approvals to frozen actions, distinguish
unknown external outcomes, and harden cancellation/recovery without weakening these
execution boundaries.
